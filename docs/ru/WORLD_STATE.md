# Состояние мира

> Русская версия. English: [../WORLD_STATE.md](../WORLD_STATE.md).

## Правило

> **СОСТОЯНИЕ МИРА НА СЕРВЕРЕ = ПОЛНОЕ. СЕТЕВАЯ РЕПЛИКАЦИЯ КЛИЕНТУ =
> ОПТИМИЗИРОВАННАЯ.**

Сервер хранит каждую сущность, всегда. Расстояние, радиус стриминга и полоса
влияют на то, *как часто* сущность отправляется конкретному клиенту, и никогда —
на то, *знает* ли о ней сервер.

Это центральное ограничение фреймворка, и оно обеспечивается структурно, а не
соглашением: `ServerWorld` — единственный класс, которому позволено добавлять и
удалять сущности, и в нём вообще нет пути удаления, знающего о расстоянии. Нет ни
`RemoveDistant`, ни `CullByRange`, ни вытеснения по стримингу. Сущность покидает
мир, когда она действительно уничтожена, и ни в какой другой момент.

## Почему это важно

Пять игроков в Лос-Сантосе, Сэнди-Шорс, Палето-Бэй, Форт-Занкудо и Грейпсид
находятся в одном мире. Проект, основанный только на близости, тихо превратился бы
в пять несвязанных одиночных игр, которые изредка замечают друг друга. Все
последствия, которые людям реально важны — погоня, начавшаяся в Сэнди-Шорс и всё
ещё идущая, когда вы приезжаете; машина, которую вы припарковали в Палето и
которая всё ещё там; миссия, которая продолжает продвигаться, пока вы едете через
карту — зависят от того, что сервер продолжает симулировать и помнить сущности,
рядом с которыми сейчас никто не стоит.

`StressTests.DistanceNeverRemovesAnEntityFromTheServerWorld` — регрессионный тест:
100 сущностей, разбросанных по углам карты, один подключённый игрок, и через 20
секунд и сервер, *и* этот игрок знают обо всех 101.

## Состав

```
WorldState
├── Tick               монотонный счётчик симуляции
├── ServerTime         секунды с запуска сервера; шкала, по которой интерполируют клиенты
├── Environment        часы, погода, ветер, отключение света
└── Entities           EntityId → NetEntity, без какой-либо фильтрации по расстоянию
```

### Окружение

| Поле | Примечания |
| --- | --- |
| `TimeOfDaySeconds` | 0–86399, продвигается каждый тик на `ClockScale` |
| `ClockScale` | игровых секунд на реальную секунду; 30 совпадает с одиночной GTA V |
| `WeatherHash` / `NextWeatherHash` | хеши joaat, поэтому мод погоды не требует изменений протокола |
| `WeatherTransition` | смешивание 0–1 |
| `WindSpeed` / `WindDirection` | |
| `Blackout` | |

Окружение передаётся в заголовке снапшота и только когда оно изменилось
(`SnapshotTests.EnvironmentIsSentOnlyWhenItChanges`). Оно крошечное, и оно нужно
каждому клиенту независимо от того, где он стоит.

Клиент применяет часы, только если они разошлись больше чем на 20 игровых секунд:
запись каждый кадр заставляет небо мерцать.

## Приоритет репликации

Приоритет — *единственное* место, где читается расстояние.

```
score(entity, viewer) =
    ни разу не отправлялась     → +∞                (входящий клиент сходится быстро)
    иначе                       → близость × вес типа × 1000 + залежалость

    близость   = 1                      если расстояние ≤ 150 м
                 150 / расстояние       дальше
    вес типа   = 4 для игроков, 1 иначе
    залежалость= тиков с момента, когда эта сущность последний раз отправлялась
                 этому клиенту
```

Из формы этой функции следуют два свойства:

- **Близкое обновляется часто.** Близость доминирует для всего, что в поле зрения.
- **Далёкое всё равно обновляется.** Залежалость растёт неограниченно, поэтому
  сущность, рядом с которой никого нет, рано или поздно обходит близкую
  неподвижную и отправляется. Никто не голодает.

## Измерения

Измерение — это параллельная копия мира: инстанс, приватная сессия, интерьер,
внутрь которого снаружи заглядывать не должны. Оно есть у каждой сущности.

Это **фильтр репликации и ничего больше**, ровно как дистанция. Сущности, чьё
измерение отличается от измерения смотрящего, ему не отправляются; ни одна из них
не покидает `ServerWorld`, и
`DimensionTests.ADimensionNeverRemovesAnEntityFromTheServerWorld` проверяет обе
половины сразу — пять машин в пяти измерениях, невидимых для единственного игрока,
и все шесть сущностей в мире.

Принадлежность — строгое равенство. Исключения «измерение 0 видит всё» намеренно
нет: правило с особым случаем приходится держать в голове на каждом месте вызова.

Уход из измерения **удаляет** сущности старого измерения у клиента, а не оставляет
их. В этом различии — вся реализация. Сущность, выпавшая из списка кандидатов, но
не объявленная удалённой, навсегда остаётся у клиента копией из baseline, застыв в
том, что делала в момент ухода из вида. Поэтому `SnapshotCodec.Write` принимает
предикат видимости и сообщает «больше не видно тебе» тем же каналом, что и «больше
не существует».

Пока этого фильтра не было, поле было декоративным: `Dimension` сериализовалось,
сохранялось, восстанавливалось при переподключении, печаталось админ-консолью и
задавалось через `TeleportPlayer`, а два игрока в разных измерениях видели друг
друга, въезжали друг в друга и стреляли друг в друга.

## Тик сервера

```
Tick(now):
  1. приём датаграмм            маршрутизация по endpoint; сначала без соединения
  2. обработка сессионных сообщений   валидация и применение ввода клиента
  3. продвижение мира           счётчик тиков, время сервера, мировые часы
  4. снапшоты (с частотой снапшотов, для каждого клиента)
  5. уборка сессий по тайм-ауту
  6. сброс peer'ов
  7. сохранение (с интервалом сохранения)
```

Время передаётся снаружи, а не читается из часов, поэтому весь сервер можно
детерминированно вести из теста. `TestHarness` именно это и делает: виртуальное
время, виртуальная сеть, нигде в наборе тестов нет сна.

## Отключение и переподключение

Когда игрок отключается:

1. его состояние записывается в хранилище;
2. его тело покидает мир (настраивается через `keepDisconnectedBodySeconds`, по
   умолчанию 0 — замороженный призрак посреди улицы хуже, чем отсутствие);
3. **его сохранённое состояние не покидает сервер.** Оно привязано к токену
   личности.

Когда он возвращается:

1. токен личности распознаётся;
2. создаётся новая сущность и инициализируется из сохранённой записи — позиция,
   здоровье, броня, модель, уровень розыска, измерение, интерьер;
3. клиент получает **полный снапшот мира таким, каков он сейчас**.

Последний пункт — требование мастер-промпта, и модель базовых представлений даёт
его бесплатно: у переподключающегося клиента нет истории, поэтому его baseline —
`Empty`, поэтому первый снапшот полный.
`SessionTests.AReconnectingPlayerReceivesTheCurrentWorldNotAnOldOne` проверяет,
что вернувшийся игрок видит, где другой игрок *сейчас*, и мировые часы такими,
какие они *сейчас*, а не какими они были, когда он уходил.
